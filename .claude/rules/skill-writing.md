# skill の書き方

`basic/01-create-skill` を基準にする。そのうえで、このリポジトリで守ること。

## description は発動条件を書く

description だけで「いつ使うか」が決まる。Routine から呼ばれる skill は呼び元の Routine 名とトリガーを、
手動の skill は発話例を書く。他 skill が読むだけの skill は「人が直接呼ばない」と書く。

## 規則の家は 1 つ

同じ規則・同じ表・同じ数値を 2 つのファイルに書かない。正本を 1 か所に置き、他は
`` `routine-common` の「見出し名」に従う `` のように見出し名で参照する。しきい値（時間・回数）は
その判定を実行する skill にだけ置く。README は概念と流れと参照先だけを持ち、規則を持たない。

## 読み手で分ける

全員が毎回読むものだけ SKILL.md に置く。一部の読み手だけが要る手順は `references/` に分け、
SKILL.md から「誰がいつ読むか」を示す。配布する雛形は `assets/` に置く。

## 理由を書き、締め付けない

「例外なし」「1 バイトでも」のような強調ではなく、なぜその規則が要るかを一文添える。
起きた問題に張り付いた規則を足す前に、ゴールと理由で書き直せないかを考える。
plugin にプロジェクトの固有名詞を書かず、プロジェクトごとの調整は対象リポジトリ側の custom skill に逃がす。

## 直したら参照を確かめる

見出し名で参照しているので、書き換えたら `grep -r '「'` で参照文字列を集め、参照先の見出しが
実在することを確認する。
