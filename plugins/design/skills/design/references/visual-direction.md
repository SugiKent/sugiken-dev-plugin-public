# 視覚の方向性を決める

新しい画面やページを作るとき、既存の見た目の方向性を変えるときに `design` スキルから読む。依頼に合わせて選んだ方向性を持ち、テンプレート然とした既定値に流れないためのもの。

## 題材から始める

依頼が何のプロダクトか、何の題材かを書いていなければ、デザインの前に自分で決めて案として示し、ユーザーに確かめる。決めるのは 3 つ。具体的な題材、誰が使うか、このデザインの主な役割。

独自の見た目は題材の側から出てくる。その業界の素材・道具・言葉づかい・慣習を拾う。小学生向けの玩具と金融アナリスト向けのダッシュボードでは、見た目はまるで違うはず。文言も仮置きで済ませず、題材に即した中身で組む。仮の文言のままだと、レイアウトの良し悪しを判断できないため。

## ページの冒頭

Web ページで最初に目に入る領域には、題材の世界でいちばんそれらしいものを、合う形で置く。見出し、画像、アニメーション、動くデモ、触れる要素など。大きな数字と小さなラベル、補助の統計、グラデーションのアクセントという組み合わせは既定値なので、それが本当に最善のときだけ使う。

## AI が作るデザインに出やすい既定値

いまの AI 生成デザインは次の特徴に寄りやすい。

1. クリーム色（`#F4F1EA` 付近）を背景に敷き、コントラストの強いセリフ体を見出しに使い、テラコッタ色（`#D97757` 付近）をアクセントに置く組み合わせ。この色は Claude 自身の画面のアクセント色でもあり、ユーザーの依頼の中では AI 生成の印に見える
2. ほぼ黒の背景に、鮮やかな黄緑か朱色のアクセント 1 色
3. 細い罫線、角丸なし、新聞のような詰まった段組み
4. 同じ角丸カードに中身を切り分け、階層に関係なく同じ角丸、同じ薄い灰色の影（`rgba(0,0,0,.1)`）、飾りのグラデーション
5. 題材に関係なく出る型の部品。見出しごとの字間を空けた大文字ラベル、中黒でつないだ補足（`A · B · C`）、`語 — 断片` 形式のラベル、黒の代わりの `#0B0B0B` や `#111`、小さなデータラベルだけの等幅書体、リンクやボタンの末尾の `→`

どれも依頼によっては正しい選択になる。ただ、題材に関係なく出てくる既定値であって、選んだ結果ではない。依頼が方向性を指定していればそれに従う。依頼の言葉は、ここに挙げた見た目を求めている場合も含めて常に優先する。依頼が決めていない軸を、これらの既定値で埋めない。

## 計画してから組む

### 1. 計画を書く

コードの前に、短い計画を書く。

- 配色: 基本の色を 4〜6 色、名前と hex 値で
- 書体: 使う書体と役割。この題材のために選ぶ。どの案件でも手に取る定番の書体は、それだけで既定値の見た目になるため。『The Elements of Typographic Style』の考え方に沿って文字サイズの段階を決め、太さ・幅・字間を意図して設定する。見出しや視覚要素として使う文字は、中身を運ぶだけの器にせず、組み方そのものをデザインの一部にする
- レイアウト: 1 文の説明と ASCII のワイヤーフレームで、複数の案を並べて比べる。左揃え・中央揃え・両端揃えのどれにするかも決める
- 原則: このページを他と分ける考え方を数行で

### 2. 計画を依頼と突き合わせる

似た依頼を受けたら自分がどこに行き着くかを想像し、計画の中でそれと同じになる部分を探す。どの似た依頼にも出す既定値になっている部分は、この依頼に合わせて直す。何を変えたか、なぜかを書く。直し終えてからコードを書き始める。

### 3. 組む

CSS の詳細度がぶつからないように書く。`.section` のような種類のクラスと `.cta` のような要素のクラスが打ち消し合い、セクション間の padding や margin が意図どおりにならないことが多い。

### 4. 見直す

組みながらスクリーンショットで見直す。試した方向性をメモに残せる場所があれば残す。次に作るとき、同じ方向に戻らずに済む。
