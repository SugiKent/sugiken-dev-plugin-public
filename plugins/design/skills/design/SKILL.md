# デザイン

利用者がどの対象について何を判断し、どの操作で仕事を終えるかを、実例で一つ通す。既存画面の限定修正では依頼の範囲を守る。再設計では現在の項目や配置から出発せず、利用者が必要とする順に組み直す。

* 判断に使う情報、編集の影響範囲、その結果に対する操作を同じまとまりに置く。一覧なら何を見比べるかで列を選ぶ。対象が違う情報や過去の履歴は必要なときに開ける位置に置く。
* 操作を始めた人の視線を追う。待ち時間には何ができるか、終わった瞬間に何が変わるかを、その対象の行や操作部で伝える。長い入力の完了など、区切り自体が大切なときは、その場ではっきり知らせる。
* 親画面も含めて文言を読み、同じ名前や操作の説明を整理する。長い一覧では、選択した場所と読み終えた場所の両方で次の操作が必要になることがある。業務上の採用語とアクセシブルな名前を保つ。文言を決めるときは `stop-describing-ui` を使う。
* apply では、実データ相当の量で入口から結果まで操作する。待ち時間のある操作は応答を保留し、変更中の対象と引き続き使える対象を同時に見る。長い画面は操作直後のスクロール位置、分割画面はペインの実幅と隣接・固定要素を含めて見る。該当する入力・保存・再読込、フォーカス、コントラスト、動きを減らした表示も確かめる。直した箇所は同じ条件で再確認し、証拠と未確認の状態を記録する。

フローの診断には `ux-heuristics`、作り直しの大きい複数案の比較には `concept-synthesis` を使う。新しい見た目を決めるときは[視覚の方向性](references/visual-direction.md)を参照する。
