# basic plugin

汎用スキルと PostToolUse フックに加えて、長いセッションの直近の会話を Haiku で図にまとめ、右ペインに表示する Claude Code mod `session-digest` を同梱しています。

## インストールと確認

```sh
claude plugin install basic@sugiken-dev-public
# インストール済みの場合
claude plugin update basic@sugiken-dev-public
```

ローカルのソースを試す場合は、開発対象のプロジェクトルートから起動します。

```sh
claude --plugin-dir /absolute/path/to/sugiken-dev-plugins-public/plugins/basic
```

Claude Code CLI v2.1.287 以降が必要です。起動後、`/plugin` の mod 一覧で `basic` が読み込まれていることを確認してください。インストール済みのセッションでは `/reload-plugins` または再起動で更新を読み込みます。

## session-digest ペイン

長いセッションで、人間が会話を読み返さなくても今の状況と押さえるべき変化を掴めるようにするためのペインです。セッション開始時には起動しません。対話型の terminal / Desktop で `/session-digest on`（または引数なしの `/session-digest`）を打ったときだけペインを開き、要約を始めます。

### 何を要約するか

Haiku（`haiku` エイリアス）には、メインの会話の直近2万文字を渡します。最後の応答だけを渡すのではないので、最後のターンが小さくても、それまでの流れを踏まえた要約になります。会話記録に含めるのは次のとおりです。

* ユーザーの依頼
* エージェントの応答文
* 呼んだツールの名前と、引数の先頭200文字（エラーになったものには印を付けます）

ツールの結果は長いので含めません。エージェントの応答文に、結果から分かったことが書かれているためです。`$.session.messages()` で会話を読めなかった場合は、ターンの最終応答だけを渡します。

Haiku はテキストの図を 1 つだけ返します。毎回同じ場所を見れば同じ情報が分かるよう、図は必ず次の 4 つの欄をこの順で並べます。

* `■ セッションの目標`：ユーザーがこのセッションで達成したいこと。記録から分からなければ「未確認」
* `■ 現在のタスク進捗`：段階を `【済】`・`【今】`・`【未】` の行に分けて並べ、量を `███░░ 3/5` で示す
* `■ やっていることの概念図`：次の型から 1〜2 個を選んで描き、図ごとに直下へ 1 文を添える
  * 構造：部品・システム・人の関係を `[箱]` と矢印、字下げの木（`├ └`）で描く
  * 因果：原因と結果の連鎖を `原因 ──▶ 結果` で描き、枝分かれは `┬` で分ける
  * 流れ：データや処理の通り道を縦の `│ ▼` でつなぎ、件数や値を添える
  * 変更：仕様・方針の旧と新を `[旧]【廃止】──▶ [新]【採用】` で示す
* `■ ユーザーへの依頼`：ユーザーの判断や作業を待っていること。選択肢があれば `【要判断】` から `┬` で A / B に分ける。無ければ「なし」

依頼が無いときも欄は省かず「なし」と書かせます。欄の有無で位置がずれないようにするためです。

システムプロンプトには「会話の抜粋 → 図」の few-shot を 4 つ入れています。日本語は端末での表示幅が揃わず右側の枠線がずれるので、箱は `[ ]` で書かせ、右を閉じる枠線は描かせません。

状態は `【済】` `【今】` `【未】` `【採用】` `【廃止】` `【失敗】` `【原因】` `【注目】` `【要判断】` の【】付きの短い言葉で示させます。`✓` `✗` `★` `!` `?` のような記号は、完了なのか問題なのかを読み手が見分けにくいため使わせません。値の不一致だけは `≠` で書かせます。ラベルは全角12文字以内で、「修正」のような一語ではなく「aud修正」のように対象を入れさせます。文には記録にある固有名と数値を使わせ、「重要な」「〜と考えられる」のような評価やぼかし、確定していないことの断定は禁じています（`01-humanizer-ja` と日本語技術文書の文章規範に沿った指示です）。4 つの欄の見出し以外の見出し・凡例・箇条書き、ファイル単位の作業や細かい手順は描かせません。Haiku がコードブロックの外に文章を付けた場合、ペインには最初のコードブロックだけを表示します。

### いつ要約するか

`/session-digest on` で起動した後、次の 3 つのタイミングで Haiku を呼びます。呼び出しはエージェントの作業とは別に行うので、作業も次のプロンプトも待たせません。

* ユーザーがプロンプトを送信したとき（mod API の `prompt.submit`）：送信したプロンプトを会話記録の末尾に加えて渡します。会話記録にすでに入っていれば二重には加えません。
* ステップが 10 回進むごと：ステップは、1 ターンの中で Claude Code がモデルへ送るリクエスト 1 回です（mod API の `turn.step`）。モデルは 1 回のリクエストで考え、文章を書き、ツール呼び出しを決めます。ツールを並列で複数呼んでも 1 ステップです。
* ターン終了時

ステップの数はメインの会話だけで数え、サブエージェントのステップとターンは数えません。数はターン終了時と Haiku を呼んだときに 0 に戻ります。次の呼び出しは「直前の要約から何ステップ進んだか」で決まるので、同じ記録を短い間隔で二重に要約しません。

Haiku の呼び出しは重なりません。前の要約が終わる前に次の呼び出し時期が来た場合、その呼び出しは待ち、さらに新しいものが来れば古いほうを捨てて最新だけを残します。会話は呼び出す直前に読むので、待った後の要約にも最新の会話が反映される仕組みです。

間隔は `/config` の plugin 設定 `digestEverySteps`（既定値 10）で変えられます。`0` にするとステップごとの要約は止まり、プロンプト送信時とターン終了時だけになります。

### 費用と待ち時間

1 回の入力は最大2万文字なので、呼び出し回数が増えても 1 回あたりの費用と待ち時間は変わりません。50 ステップのターンでは、プロンプト送信時・10 ステップごと・ターン終了時を合わせて 7 回になります。認証は Claude Code セッションのものを使うため、API キーは不要です。

### 表示と操作

表示内容は上から次のとおりです。

* `Haiku: <状態>`：状態はリクエスト中、応答待ち、応答あり、失敗、スキップのどれかです。まだ一度も要約していないときは表示しません。応答ありにはユーザー入力時・何ステップ時点・ターン終了時のどれかと所要時間（ms）が、失敗には理由と HTTP ステータスが付きます。
* 「再要約」「閉じる」ボタン
* Haiku の図
* 最下部に mod の version（`session-digest vX.Y.Z`）

右ペインの希望幅は画面幅の約30%です。Claude の最低幅・配置ルール、ドラッグ等で調整した幅が優先されます。

| コマンド | 動作 |
| --- | --- |
| `/session-digest on` | ペインを開いてフォーカスを移し、要約を始める |
| `/session-digest refresh` | 直近の会話をすぐに要約する |
| `/session-digest` | `on` と同じ |
| `/session-digest off` | ペインを閉じ、このセッションの要約を止める |

ペインが描画されるのは terminal と Desktop の Code タブだけで、VS Code のチャットパネルや `claude -p` には出ません。

## 検証

```sh
claude plugin validate plugins/basic
claude plugin test plugins/basic
```

mod のテストは実セッション・ログイン・通信・モデル呼び出しを使わずに、イベントと描画ツリーを検証します。会話記録とモデルの応答はテスト内で差し替えます。実画面のレイアウト確認は別途必要です。

mod の API は次の公式ドキュメントを参照してください。

* [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview)
* [Draw in the interface](https://code.claude.com/docs/en/plugins/mods/interface)
* [Test a mod](https://code.claude.com/docs/en/plugins/mods/test)
