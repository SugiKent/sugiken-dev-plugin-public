# Sequence Work into Verifiable Units（検証できる単位に並べる）

この原則は、複数手順の作業（一括修正、移行、似た編集の連続）と、コミットや PR の積み方に当てる。作業を、それぞれ確かめられる状態で終わる小さな単位に分け、次へ進む前に今の単位を確かめ、並べた順そのものがレビュアーへの証明になるように届ける。

作業を小さな単位の列にし、各単位を確かめられる状態で終える。今の単位が緑になるまで先へ進まない。

**理由。** 壊れたものを、それを起こした単位で捕まえれば、場所の特定は安い。まとめて進めた後で捕まえると壊れた場所が埋もれ、既に壊れた土台の上に積み上げている。同じ単位を、レビュアーが再生できる順に届ければ、「信じて」が「赤から緑になるのを見て」に変わる。

**実行。** 一括修正、移行、似た編集の連続では、次の変更に入る前に今の変更を確かめる。各単位は前後を挟む括弧になる。正常な状態、1 つの変更、確認の実行、そして次へ。まずきれいな trunk に rebase し、どの確認も本物の基準と比べるようにする。てこ（[Build the Lever](build-the-lever.md)）が編集をするなら、単位ごとの確認はほぼただになる。それでも毎回実行する。

**届け方。** コミットと PR を、作業を証明する順に積む。基本形は、失敗するテストが先で、その上に修正。ほかの順序としては、作り変えの前の引き算、手当ての前の基準値の記録、機能の前の足場がある。各コミットは単独で取り込めて、並びが一つの論証として読める。

[Prove It Works](prove-it-works.md)（各確認を本物に保つ）の、順序の面からの補完。単位ごとの確認を安くするのは [Build the Lever](build-the-lever.md)。
