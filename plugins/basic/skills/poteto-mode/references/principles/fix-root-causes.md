# Fix Root Causes（根本原因を直す）

デバッグのときに当てる。症状をたどり、システムが最初に誤った場所で直す。ガードが修正になるのは、そのガードが扱う状態が正当なときだけ。

デバッグでは、故障そのものを直す。症状が出た場所を直しても、故障は残る。症状は、誤った状態が見えるようになった場所。根本原因は、システムがすべきでないことをした、または扱うべき状態を扱えなかった最初の場所。

**理由。** 症状だけを直すと証拠が隠れ、故障はまた別の場所に出てくる。症状への修正が増えるたびにシステムは推論しにくくなる。誰も名付けていないバグのための回避策を、コードが抱えることになるため。

**やり方。**

- まず再現する。
- 一歩ごとに「なぜ」を問い、答えがコードの中の誤った判断そのものになるまで続ける。前の誤りの結果に行き着いただけなら、まだ途中にいる。
- 行き詰まったら計装する。実際のエラーと実際の状態を読む。推測しない。
- 症状を起こした状態が正当かを問う。システムがその状態になってよいなら、その状態で壊れたコードが根本原因で、そこでその状態を扱うのが修正になる。その状態が決して存在してはいけないなら、壊れた場所の検査はバグを隠す。その状態を作ったものを探す。ガード、再試行、握りつぶしたエラー、丸めた値、捨てた状態が、バグを隠すいつもの手口。
- 再起動の後だけ失敗するなら、まず永続化された状態を疑う。疑う先は、設定ファイル、キャッシュ、ロックファイル、シリアライズした状態。
- 一件を直したら、同じ型を探す。同じ故障を持つ場所をすべて見つけ、全部直す。
- 回避策の言い訳に段落ほどのコメントが要るなら、コードが間違っている。直すのはコードで、コメントを磨いても故障は残る。
- 決め手になった事実を見つけるのに深く掘る必要があったなら、最初の一目でそれが見える、安くて常に出ている信号を提案する。
