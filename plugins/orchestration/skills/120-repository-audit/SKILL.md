# リポジトリの品質点検

## 目的

リポジトリ全体の問題を見つけて改善し、繰り返す問題を lint・rules・skills で防ぐ。

## やること

対象リポジトリの仕様と既存の検証方法を確認し、次の項目を点検する。

* **コメント**: 不要なコメントを削除し、TODO を実装で解消する。必要なコメントを残し、不要なコメントの増加を lint で防ぐ。
* **アーキテクチャ**: 責務と依存方向から設計を見直し、既存の動作・公開 API・DB 契約を保って改善する。設計方針を rules、機械判定できる境界を lint にする。
* **セッション分析**: 過去の訂正・失敗・やり直しから繰り返す問題を見つけ、lint・rules・skills に反映する。
* **lint・test・dev 高速化**: 検証や開発サーバーの遅い部分を測定して改善する。同じ条件で前後を比較し、検証範囲とテスト網羅を維持する。
* **セキュリティ**: 依存、秘密情報、認証・認可、入力、外部通信、ログ、権限設定を点検して修正し、テストや lint で再発を防ぐ。
* **不要ファイル**: 参照と用途を確認して不要ファイルを削除する。一時ファイルの置き場を整理し、不要な混入を lint で検知する。
* **モダン化**: 開発ツール・依存・設定を更新する。ライブラリと Docker イメージは脆弱性情報を確認し、脆弱性報告がない最新の版を選ぶ。
* **E2E 高速化**: E2E が点検対象なら、時間のかかる処理を測定して改善し、網羅を維持した前後の実測値を示す。

## 検証と報告

変更後の lint・型チェック・テストで改善と既存動作を確認し、失敗の原因を修正する。各項目の修正内容、再発防止策、前後の計測値、検証結果、未実施の範囲と残件を報告する。
