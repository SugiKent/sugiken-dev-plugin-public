# E2E 実行・結果報告スキル

**目的**: E2E を正しくヘッドレス実行し、結果と原因の見立てを回収して返す。**修正はしない**（直すのは呼び出し側の実装フェーズ = [[30-implement-e2e]] の仕事）。

> `context: fork` で subagent 化して走る。会話履歴は引き継がないため、**実行対象と前提（DB reset 要否など）は起動プロンプトから受け取る**。

## 厳守事項

* **修正禁止**: テスト失敗を見つけても、実装ファイル・E2E テストファイル・設定を書き換えない。事実と見立てだけを返す。
* **実行管理**: 下の「共通の実行管理」に従う。
* **CLI を E2E に流用しない**: 動作確認用 CLI を E2E の検証手段に使わない。
* **実行系は自分で担う**: Playwright / ブラウザ・Maestro / シミュレータ起動を伴う実行は他に委譲できない（ポート制限）。fork 内で自分でヘッドレス実行する。

## 共通の実行管理

この節は `30-implement-e2e` のその場実行にも適用する。40 本体の修正禁止は、30 の実装・修正には適用しない。

* 起動前に共有ポート・DB・端末などの資源を特定し、既存の排他手段で所有を取得する。なければ資源ごとのロックを排他的ファイル作成や `mkdir` などで原子的に取得する。確認してから heartbeat を書くだけでは排他にならない。独立した資源は並行利用してよい。取得途中で失敗した場合は自分が取得した分だけ解放する。
* 所有者の run ID、対象資源、PID または実行セッション、ログと終了コードの保存先、開始時の HEAD と未コミット差分の要約を記録する。共有の作業ツリーでは実行中にもコードが変わるので、結果をどのコードに結び付けるかを残す。回収時に HEAD か差分が変わっていたら、結果は「変更前のコードの結果」として報告する。既存の `E2E_HEARTBEAT.md` に他者の記述があれば上書きしない。同じ資源の利用中、または資源を判別できなければ待つか報告する。自分の所有を確認した範囲だけ更新・解放する。
* 実行が終わるまで担当を維持し、終了コードとログ・ケース別結果を回収する。長い処理は実行セッションを継続して待ち、起動しただけでターンを終えない。PID の消失や長い無出力だけで成功・失敗・ハングと判定しない。
* 失敗を環境・他の作業由来とするときは、変更前のコードで同じ失敗が出ることを確かめたか（確認済みなら根拠）、未確認かを書く。未確認の失敗は「無関係」に数えず、報告でも別に数える。確かめないまま無関係とすると、自分の変更が起こした失敗を見逃すため。変更前のコードでの再実行は、起動プロンプトが指示したときだけ行う。別の worktree か共有の作業ツリーの切り替えが要り、資源の確保が二重になるか他者の作業を乱すため。
* 中断から再開したら、自分の run の生存と保存済み結果を先に確認し、二重起動しない。結果が失われていれば未確認と報告する。実行終了を確認して自分のロックと heartbeat 記述だけを解放し、他者や所有不明の記録を古いという理由だけで消さない。

## 手順

1. 起動プロンプトの実行対象（対象ドメイン、例 `C-01x` / 全ケース）と前提（DB reset 要否）を確認する。既定は起動プロンプトが渡したケースだけを実行し、全件は起動プロンプトが全件実行を明示したときだけ流す。実行対象が書かれていなければ全件に倒さず、「実行対象未指定」として報告する。
2. 共通の実行管理に従って資源を確保し、ヘッドレス実行する：
  * Web: `npx playwright test`（特定: `npx playwright test e2e/tests/auth/`、ケース ID: `--grep "C-01[0-9]"`、失敗のみ: `--last-failed`）
  * モバイル: `maestro test .maestro/flows/`（tags: `maestro test --include-tags smoke`）
3. 終了コード・ログ・ケース別結果を回収し、自分の実行資源を解放する。
4. 失敗ケースごとに、エラー内容・再現条件・**原因の見立て（実装側の不具合 / E2E 側の記述 / データ前提 / 環境・他の作業由来）**を添える。**ただし修正はしない**。環境・他の作業由来の扱いは「共通の実行管理」に従う。trace（Web: `test-results/<name>/trace.zip`）は読んで見立てに反映してよい。

## 報告フォーマット（親エージェント／人間へ返す）

```
## E2E 実行結果
* 実行対象: <ドメイン or 全ケース> / DB reset: 実施/未実施
* サマリ: N passed / M failed（うち環境・他の作業由来で未確認 U）/ K skipped / L 未実行
* run ID / 終了コード / ログ: <根拠の保存先>
* 実行したのは HEAD <sha> に <未コミット差分の要約> を加えたコードで、回収時に変わっていれば「変更前のコードの結果」と添える
### 失敗ケース（あれば）
* <ケース ID / 名前> は <エラー要点> で落ちた。見立ては <実装側 / E2E 側 / データ前提 / 環境・他の作業由来> とする
  * 環境・他の作業由来と見立てたら、変更前のコードでの再現を <確認済み（根拠）/ 未確認> で添える
### 所感
* 全体緑か、どこを直せば緑になりそうか（修正は呼び出し側に委ねる）
```
