まず同じ plugin の `routine-common` skill を読み、そのラベル規約に従う。

# 前提（無人実行）

このスキルは定期実行の Routine から**無人で**呼ばれる。対話するユーザーはいない。

- **判断に迷ったら安全側へ倒す。** 着手しない・状態を壊さない方を選ぶ。
- **何をどう数えてそう判断したかを報告する。** 数字と、それが支えた判断を書く。
- **直すものが 0 件なら、数え方を報告して終える。それが正しい終わり方である。**
  埋め合わせの作業を作らない。

通常の段階遷移と着手はイベント起動の `routine-dispatch` と worker が行う。Routines の
GitHub webhook には時間あたり上限があり超過分は黙って破棄されるうえ、利用上限に当たった
セッションは途中で死ぬ。落ちた分をここで拾う。**判定の本体は `routine-dispatch` にあり、
ここに独自の判定を置かない。**

# 順序

## 1. `routine-dispatch` を実行する

同じ plugin の `routine-dispatch` skill を読み、その 1〜4 をそのまま実行する。残骸の回収・
merge に合わせた段階の前進・ブロックの評価と放出・死んだ worker の再起動がここで済む。
worker の再起動は段階ラベルの付け直しで行い、このセッションが worker の仕事を代理しない。

## 2. 応答が止まった PR を引き継ぐ

auto-fix はセッションが受け取るので、VM が回収された後も通常は再開する。それでも止まった
ものを拾う。open PR のうち、次を満たすものを探す。

1. ラベルが `propose` または `apply`
2. 最新のコメントが人のもの（`<!-- routine -->` で始まらない）
3. そのコメントから 3 時間を超えて routine の返信が無い

見つかったら、PR のスレッド全体と diff を読み、**そのラベルに対応するスキル**
（`routine-propose` / `routine-apply`）の続きを引き受ける。auto-fix を有効化し直す。
引き継ぐのは 1 セッションで 1 件まで。

# `.claude/` `docs/` だけの修正

規約や記録の誤りに気づいたら、`routine-common` の「openspec を通さない変更」に従って
`docs` ラベルの PR を 1 本作ってよい。ただし**次のどれかに当たるなら書いてはならない**。

1. 書こうとしているファイルを、直近 24 時間に merge された PR が触っている
2. その差分が次のセッションの行動を変えない
3. open なコード PR がある（main を進めてコンフリクトの母数を増やすため）

1 を上書きできるのは、現に書いてある規約が**実測で効いていない・誤りだと数字で反証できる**ときだけ。
その規約 1 つを直し、ついでの実測値更新や言い回しの改善は混ぜない。
