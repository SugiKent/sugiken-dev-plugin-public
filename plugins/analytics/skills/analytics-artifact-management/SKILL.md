# 分析成果物の管理

## 分析過程の記録

- 仮説の追加・棄却、コホート定義変更、交絡の発見、解釈の反転など、大きな転換ごとに1ファイルを作る。
- ファイル名はタイムスタンプ + 連番 + 内容にする（例: `20260612-0210_10_バイアス補正で解釈反転.md`）。
- 各ファイルは最低限 `## 仮説` / `## 分析方法` / `## 結果` の3部構成とし、必要なら `## 注意・限界` を加える。
- 失敗・棄却した仮説も残す。なぜ捨てたかは次の分析資産になる。

## 標準フォルダ

分析ごとに `分析結果/{YYYYMMDD-HHmm}_{テーマ}/` を1つ作り、関係が分かるようサブフォルダで層別する。`HHmm` は必須で、着手順が担保される値にする。日付時刻とテーマの区切りは `_` とし、テーマ自身にはハイフンを含めてよい。

```text
hrs/drs/ca/分析結果/{YYYYMMDD-HHmm}_{テーマ}/
├── README.md          # 目的・コホート定義・フォルダ説明・実行環境・機密注記
├── report.md          # 最終レポート（経営層/依頼者向け）
├── 00_process/        # 分析過程ログ（3点セット・タイムスタンプ順）
├── 10_data/           # 抽出データ(JSONL等)・スキーマ・取得state。生PIIは置かない
├── 20_scripts/        # 抽出・分析のPython（common.py＋連番スクリプト）
└── 30_outputs/        # 集計表(CSV)・図・中間成果
```

## 機密

- 氏名・住所・電話などのPII、取引先固有情報は取得・保存を避ける。自由記述は `{present:bool, len:int}` 等に還元して保存する。生テキストが必要な分析は理由を明示し、スクリプト内で完結させる。
- 実名・取引先名を含む成果物はPush禁止・社外共有不可。別添ファイルに隔離して注記し、`note-repo-confidentiality` に従う。
