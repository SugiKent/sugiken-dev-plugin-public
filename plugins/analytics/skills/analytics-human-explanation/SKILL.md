# 分析結果を人に伝える

人間向けに結果を説明するときは、正しい分析であることだけでは不十分である。読者が社内用語・指標・統計を知らない前提で、**各ページまたは各説明ブロック単体で意味が分かる**状態を完成条件にする。

定義や統計の説明が欠けた資料を完成扱いにしない。元の分析にある限界、留保、確信度の差も削らない。

## 基本ルール

1. 読者、意思決定、使う前提知識を確認する。指定がなければ「対象業務は知るが、社内指標・統計は知らない読者」と仮定する。
1. 基本は後述の「分析の流れを説明する型」に従って書く。
1. 最初に結論を一文で書き、その直後に根拠を一行で添える。根拠には比較対象、期間、件数（n）、データ出どころのうち必要なものを含める。
1. 本文・図表・表を通して、初出の用語、略語、指標、統計表記を洗い出す。
1. 以下の「必須の翻訳」をその場で加える。用語が5語以上なら、表紙直後または冒頭に用語集を置く。
1. 最後に「1枚だけ読んだ人が、用語・比較・数字の意味・限界を理解できるか」をページごとに点検し、欠ける説明を補う。

## 必須の翻訳

### 用語・指標

- 業務固有語は初出で一行の平易な定義を付ける。本文の括弧、`callout`、用語集のいずれでもよい。
- 略語も初出で日本語名と意味を示す。例: 「CA（求職者の転職支援を担当するキャリアエージェント）」。
- `OwnerId` や `Field19__c` のような内部フィールド名は出さない。必要なら「担当CA」のような読者向けの日本語に置き換える。
- 指標には分子と分母を書く。例: 「打診転換率＝求人を打診した求職者のうち、選考に進んだ人の割合」。
- 用語が5語以上なら、用語集を `table` または `card` グリッドで用意し、本文でも初出箇所が追えるようにする。

### 数字・統計

数値だけを置かない。統計値ごとに、少なくとも次の4点を括弧または `callout` で添える。

1. 何を表す指標か
2. どちら向きの関係・差か
3. 強さまたは確かさはどの程度か
4. 何を意味しないか、どんな留保があるか

次の表現は、対応する平易な説明を必ず添える。

| 表記 | 添える説明 |
| --- | --- |
| 相関係数 `ρ` / `r = 0.23` | 「弱い正の関係。一方が高いほどもう一方もやや高い傾向。因果関係を示すものではない」（目安: 0.1=弱い、0.3=中程度、0.5=強い） |
| `pt`（ポイント） | 「割合どうしの差。66%と39%の差は27ポイントであり、27%ではない」 |
| オッズ比 `OR = 0.14` | 「他の条件をそろえた比較で、その起こりやすさが約1/7に下がる。1は差なし、1超は増加、1未満は減少」 |
| p値 / 有意 | 「その差が偶然に出る確率の目安。小さいほど偶然だけでは説明しにくい。`p < 0.05` は慣例的な目安で、重要性の大きさ自体は示さない」 |
| `95% CI`（信頼区間） | 「真の値が収まると見込める範囲。狭いほど推定が精密」 |
| `n`（サンプル数） | 「集計に使った件数。小さいほど偶然のブレが大きい」 |
| 中央値 | 「小さい順に並べた真ん中の値。平均と違い、極端な値に引っぱられにくい」 |
| ICC | 「結果のばらつきのうち、CAごとの差が占める割合。高いほど担当者による違いが大きい」 |
| 交絡 / 統制後 / within-CA | 「別の共通原因によって、見かけ上の関係が強まったり弱まったりすること。統制後は、他条件をそろえた公平な比較」 |

相関は因果と書かない。割合の差は「ポイント差」と「%」を取り違えない。元レポートが「頑健」「確証は弱い」「未確定」と区別したなら、そのまま残し、都合よく断定しない。

## ページと文章の型

- 見出しは話題名ではなく結論にする。例: 「年齢別の結果」ではなく「40代以上は打診後の選考移行率が低い傾向」。
- 見出しの下に、結論を支える根拠を一行で書く。例: 「2026年1〜6月の有効面談1,248件で、40代以上は39%、39歳以下は66%（差は27ポイント）」。
- 図表には、何を比較し、いつのデータで、何件か、単位は何かを明記する。軸・凡例・注記だけで読めるようにする。
- 主張の強さを証拠に合わせる。「〜が原因」ではなく、因果を検証していなければ「〜と関連」「〜の傾向」と書く。

## HTML で出すときの体裁

分析結果を HTML（レポート・分析メモ・ダッシュボード）で出すときは、下の作法に従う。既定のまま書くと、枠線だらけのカード・グラデーション背景・絵文字見出し・虹色の配色になり、内容の質と無関係に「AI が吐いた画面」に見える。装飾は読解の助けにならない。

構造は**線と箱ではなく、余白と文字の階層**で作る。

1. 区切りは余白。セクション境界は 64px 以上の余白＋水平の細罫 1 本まで。囲み枠は使わない。
2. 階層は文字。サイズ・太さ・黒→グレー 2 段階の濃淡で表す。背景色で表さない。
3. 色は 3 つまで。紙の白＋インクの黒グレー系＋アクセント 1 色（既定は濃紺 `#173f66`）。アクセントは面積 5% 以下で、重要な数字と構造要素だけに使う。
4. 各セクションは「見出し（トピック）→ メッセージライン 1 文（結論）→ 根拠（表・図・本文）」の順に置く。**見出しだけ読めば流れが、メッセージラインだけ読めば結論が分かる**状態にする。これは前述の「見出しは結論にする」「根拠を一行で添える」の HTML 上の形である。
5. 白背景固定・A4 印刷で崩れない。画面映えではなく配布資料として設計する。

**禁止**（1 つでもあれば直す）: `border` + `border-radius` + `box-shadow` のカード UI／グラデーション背景・ダークテーマ既定／見出し・箇条書きの飾りとしての絵文字・アイコン／意味なく増える色（青の情報ボックス、黄の注意ボックス…）／本文・見出しのセンタリング（表紙のみ例外）／表の縦罫線・全セル罫線・シマシマ背景／角丸・影・立体表現／色付き `border-left` コールアウトの乱立。

### 使うもの

書き始める前に [`references/report.css`](references/report.css) を読み、使う図表の型が決まったら [`references/report.template.html`](references/report.template.html) の該当箇所だけを開いてマークアップを引き写す。テンプレートは架空事例の完成見本なので、文章や数字を流用しない。

- スタイルは `references/report.css` を `<style>` にそのまま貼る。改変してよいのは `--accent` の 1 色だけで、新しい色・枠・影は足さない。KPI（`.kpis`）・表（`.tbl` / `table`）・図表（`figure` + `.src`）・注記（`.note`）・矢羽根（`.chevrons`）・ロードマップ（`.roadmap`）・フレームワーク表（`.matrix`）のクラスが入っている。
- 骨格は「表紙（`.doc-header`）→ エグゼクティブサマリー（`.summary` に結論・根拠・依頼の 3 点）→ 番号付きセクション（`<h2><span class="no">01</span>…` ＋ `.msg`）→ 推奨アクション（誰が・何を・いつまでに の表）→ `.doc-footer`」。
- 表は縦罫線なし、数値列は `class="num"` で右揃え・桁区切り、単位はヘッダーに書く（例:「受注数（件）」）。KPI は箱に入れず `.kpis` で横に並べ、間は縦の細罫 1 本。
- チャートは SVG で書き、**脇役はグレー、主役の 1 系列だけアクセント色**。凡例ボックスは作らず、線の右端・棒の近くに系列名と値を直接ラベルとして置く。悪化・負値を示すときだけレンガ色 `#a33c2e` を足してよい（マイナスは `▲8.0` 表記）。
- 3D・影・グラデ・チャートの外枠は使わない。棒グラフの軸は 0 を基点にする。軸線・グリッドは細いグレーを最小限に。
- 数字を見せたら `.src` で出典・集計定義・対象期間を必ず添える。出所の書かれていない数字は、会議で必ず「この数字合ってる?」に時間を奪われる。

## 分析の流れを説明する型

過去の分析セッションを含め、複数の分析が結論に至る流れを説明すること。分析ごとに見出しを分け、次の形式を使う。読者が「何を確かめようとし、なぜ次の分析が必要になったか」を追えるように、時系列・依存関係を省略しない。

```markdown
# {分析1のタイトル}

| 項目 | 内容 |
| --- | --- |
| 分析前の仮説 | {何が起きていると予想したか} |
| アプローチと狙い | {何を、どのように比較・検証し、なぜその方法を選んだか} |
| 結果 | {分かったこと。比較対象、期間、件数、主要な数値を含める} |
| 解釈 | {なぜこの結果になったと考えられるか。事実と推測を分け、限界・代替説明も添える} |

# {分析2のタイトル}

| 項目 | 内容 |
| --- | --- |
| 分析前の仮説 | {分析1の結果を受けて、次に確かめた仮説} |
| アプローチと狙い | {何を、どのように比較・検証し、なぜその方法を選んだか} |
| 結果 | {分かったこと。比較対象、期間、件数、主要な数値を含める} |
| 解釈 | {なぜこの結果になったと考えられるか。事実と推測を分け、限界・代替説明も添える} |
```

各行でも、このスキルの用語・統計の説明ルールを守る。解釈は結果の言い換えで終わらせず、結果に至る仕組みを説明する。ただし、データで確認できた事実と仮説的な理由を混同せず、因果が未検証なら「考えられる」「示唆される」と表現する。

## 提出前チェック

- [ ] 各ページ・説明ブロックだけで、結論、比較対象、対象期間・件数、単位が分かる。
- [ ] 初出の社内用語・略語・指標に平易な定義があり、内部フィールド名を読者向けの日本語に直した。
- [ ] 指標は分子と分母を示した。
- [ ] 統計値ごとに意味、向き、強さ/確かさ、留保を添えた。
- [ ] 相関と因果、ポイント差と百分率を明確に区別した。
- [ ] 重要な結論ごとに根拠を一行で示し、元分析の限界・未確定事項を残した。
- [ ] 用語が5語以上なら、用語集ページを置いた。
- [ ] HTML で出す場合: 枠で囲んだカードが 0 個、グラデ・影・絵文字・角丸が 0、色はインク系＋アクセント 1 色に収まっている。
- [ ] HTML で出す場合: 各セクションにメッセージライン（`.msg`）があり、最終セクションが「誰が・何を・いつまでに」の推奨アクションになっている。図表に出所があり、A4 印刷で表・図が泣き別れしない。
- [ ] 複数の分析セッションを説明する場合、分析ごとに仮説、アプローチと狙い、結果、解釈を表で示し、前の分析とのつながりを明記した。
