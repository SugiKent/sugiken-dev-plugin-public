# Never Block on the Human（人間を待って止まらない）

可逆な作業で「X してよいか」と聞きたくなったときに当てる。

人間は非同期に監督する。エージェントは止まらずにいなければならない。妥当な判断をして進め、後から人間に軌道修正させる。コードの変更は元に戻せてレビューできるので、誤った判断のコストは、たいてい止まって待つコストより小さい。

- 進めてから見せる。作業をして結果を見せる。「X してよいか」と聞かず、X をして理由を説明する。
- システムを自己修復させる。問題に気付いたら記録し、次の回で直す。
- 取り消せない操作（共有ブランチへの force push、本番へのデプロイ、本番データの削除、外部へのメッセージ送信）は、引き続き確認を要する。
- 可逆な操作（コードを書く、メモを直す、タスクを分ける）は止まらずに進める。
- 製品の方向は人間が決める。実行は止まらない。

SDD の propose では、仕様を左右する製品判断は `basic:grill-me` で尋ねる。尋ねてよいのは、`basic:grill-me` の「質問する前に分ける」で製品判断・好みに分類したものだけ。SDD の apply では、この原則を決まったことの実行にだけ当てる。判断が要る場面では妥当な判断で進めず、propose へ戻す。apply で決めた判断は、グリリングとレビューを通らないため。
