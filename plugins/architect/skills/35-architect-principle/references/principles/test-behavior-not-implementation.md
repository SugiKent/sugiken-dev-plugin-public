# Test Behavior, Not Implementation（振る舞いをテストする）

テストを書く・変える・残すときに当てる。コードの利用者が観測できることを確かめ、その振る舞いが壊れたら落ち、内部だけが変わったら通り続けるテストにする。

テストは、コードが利用者（呼び出し元、エンドユーザー、別のサービス）のために何をするかについての主張。振る舞いとは、利用者が使うインターフェースを通して観測できること。戻り値、エラー、読み戻せる状態、コードの外のシステムへの作用（送ったリクエスト、書いた行、出したメッセージ）が含まれる。実装とは、利用者が観測できないこと。private な補助関数、内部の呼び出し順、途中のデータ、どの内部の協力者が仕事をしたか。

各テストを、2 つの想像上の編集で量る。

- **振る舞いを壊す。** コードに誤った値を返させる、作用を飛ばさせる、作用を 2 回させる。それでもテストが通るなら、何も証明していない。よくある原因は、約束より緩い assert、テスト対象のコードで計算した期待値、読む側のコードを一度も動かさない定数やプロンプト文字列の書き写し、テスト自身が作ったデータへの assert。
- **内部を変える。** 観測できる結果をすべて同じに保ったまま、下の構造を組み替える。それでテストが落ちるなら、実装に縛られている。リファクタリングのたびに書き直しが要り、それでいてバグは捕まえない。

1 つ目の編集を捕まえ、2 つ目の編集を生き延びるテストを残す。残りは書き直すか消す。両方を満たすテストを書くには、利用者のインターフェースから具体的な入力でコードを動かす。期待値は要件から導く。コードを動かした結果を期待値にすると、今のバグまで正解として固定してしまう。約束していることを、多くも少なくもなく assert する。

決めるのは約束であって、assert の形ではない。「空のカートは決して課金しない」が約束なら、決済クライアントが呼ばれなかったという assert は振る舞いになる。課金が起きる場合と組にして、テストが呼び出しを見られることを示す。モック化した外部サービスが受け取るペイロードは、そのサービスが観測するので振る舞い。内部の補助関数への呼び出しは、どの利用者にも見えないので実装。一致するレコードがないときの空のリストは正確な答えだが、テストが何かしらの結果を要るだけなら空っぽの検査になる。エラーメッセージの文言をそのまま確かめると、どの呼び出し元も読まない文言を縛る。呼び出し元が分岐に使うエラーの型が約束になる。

テストは呼び出しの代わりに不変条件を縛ってもよい（2 つの表に必ず存在するキー、コンパイル時の型検査など）。その不変条件が振る舞いになる。

テストの追加可否と低価値テストの刈り込みは `architect:35-architect-test-audit` に従う。
