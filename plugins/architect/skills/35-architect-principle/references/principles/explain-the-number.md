# Explain the Number（数字を説明する）

計測した数字（速度向上、劣化、スループット、レイテンシ、eval の結果）を信じる・報告する・行動に使う前に当てる。数字を頭打ちにしているものを突き止め、思っている作業とは別のものを測っていないかを潰す。

- **「なぜ倍ではないのか」を問う。** 結果を頭打ちにしている資源かコードの経路（コア、ロック、ディスク、ネットワーク、負荷をかける側そのもの）を名指しする。原因は、実行中に取ったプロファイルかシステムのカウンタから突き止め、ソースに対応付ける。コードを読んだだけの推測は、頭打ちの原因にならない。数字がなぜ 2 倍よくないのか言えないなら、何を測ったのか分かっていない。
- **その数字がほかに何を測っていそうかを並べ、それぞれを証拠で潰す。** よくある容疑者は、エラー、飛ばされた・キャッシュされた処理、一度も動かなかったコード、調整されていない側（既定設定のまま放置した側）、ノイズ、端から端では意味のないほど小さな部分。
- **証拠を数字と一緒に置く。** 実行回数、ばらつき、頭打ちの原因を、メモか紐付けた成果物に書く。

eval の結果では、試行に同じことを問う。すべての実行が課題をこなしたか、差は試行とモデルをまたいで保たれるか、シナリオに意味があるか。

この原則を飛ばした印は、数字の裏の証拠に実行回数・ばらつき・頭打ちの原因のどれかがないこと。または、短縮したと主張する時間が、変えた部分にかかっていた時間より大きいこと。

[Prove It Works](prove-it-works.md)（出力が本物かを確かめる）とは別物。
