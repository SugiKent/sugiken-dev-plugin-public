# Outcome-Oriented Execution（到達点から逆算して進める）

段階の区切りを決めた書き直しや移行のときに当てる。目標の構造へ収束させ、使い捨ての互換コードで途中の状態をなめらかに保とうとしない。

途中の状態を守ることより、意図した、確かめられる最終状態を優先する。

**理由。** 途中のどの段階も完全に安定させようとすると、一時的な互換コードが生まれ、それが長生きする負債になる。目標の構造へ収束させ、明示した検証の区切りで正しさを証明する。

**中心の規則。**

- 移行中の安定より、最終状態の正しさを優先する。
- 計画し、範囲を決め、元に戻せる途中の破損は受け入れる。

**ガードレール。**

- 段階の区切りを明示した、計画済みの書き直しと移行にだけ使う。
- 一時的な破損を許す場所を宣言する。
- 移行中も、実際に触っている領域には信号の強い検査を残す。
- 計画の完了時には、静的・実行時の検証を全部通す。
