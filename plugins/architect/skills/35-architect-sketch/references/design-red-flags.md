# 設計の赤旗

統合の前に、すべての候補をこれで選別する。赤旗は、その形を直すか退ける理由になる。

## 浅いモジュール

浅いモジュールは、大きなインターフェースを出しながら、隠す複雑さが少ない。深さは、公開面の大きさに対して、その後ろに隠した能力と方針の量で量る。単純なインターフェースの後ろに、中身のある振る舞いがあるものを選ぶ。

深いモジュールと、深い呼び出しの連鎖を混同しない。深い呼び出しの連鎖は、理解を層に散らす。深いモジュールは、能力を 1 つのインターフェースの後ろに集める。

見るべき兆し。

- 呼び出し元が、1 つの操作を終えるために複数のメソッドを調整する。
- 公開の選択肢が、内部の段階や実装の選択をさらしている。
- インターフェースを覚えても、呼び出し元が実装を覚えずに済まない。

## 情報の漏れ

情報の漏れでは、複数のモジュールが同じ内部の判断に依存する。表現・方針・プロトコルの詳細が 2 か所以上に現れ、それを変えるには協調した編集が要る。

通信やワイヤ形式の型を公開面から再 export するのは漏れになる。外部データはインターフェースの後ろでドメインの型にパースする。保存のスキーマ、フレームワークのオブジェクト、プロトコルの詳細は private に保つ。

## 時間順の分割

時間順の分割は、モジュールを持つ知識で分けずに、実行の順番で分ける。読み込み・検証・変換・保存を別の段階にすると、1 つの表現とその不変条件を、いくつもの境界で繰り返しがちになる。

コードはドメインの知識と所有の周りにまとめる。違う時刻に動くメソッドでも、同じ判断を守るなら 1 つのモジュールに属してよい。

## 素通しのメソッド

素通しのメソッドは、同じ引数を同じ形の別のメソッドへ渡すだけ。複雑さを隠さずに層を足す。

消すか、操作を終えられるモジュールへ責任を移す。転送の境界を残すのは、方針・変換・別の抽象を足すときだけ。

## 割れた所有

複数のモジュールが同じ状態に書き込む、またはそれぞれが状態の写しを持つ。1 つの書き手を編集したエージェントにはほかの書き手が見えず、規則が食い違っていく。

状態ごとに持ち主を 1 つにする。ほかのモジュールは読むか、持ち主に変更を頼む。

## 1 つの作業に 2 つのやり方

設計が、同じ作業に複数のやり方を許している。エージェントは最初に見つけたやり方を写すので、どのやり方も呼び出し元を増やし続ける。

やり方を 1 つにする。呼び出し元をほかのやり方から移し、同じ変更でそれらを消す。

## import できる内部

呼び出し元がモジュールの内部を import できる。エージェントはコンパイルが通る最短の道を取るので、内部を直接 import し、それがインターフェースの一部になる。

内部をモジュールの外から届かないようにし、外からの import でビルドが落ちるようにする。

## 手で同期する一覧

2 か所以上が同じ項目を並べていて、項目を足すたびに全部の一覧を編集する。1 つの一覧を見たエージェントは、その一覧だけを更新する。

一覧を 1 つにし、ほかはそこから導く。導けない一覧なら、一覧同士が食い違ったときにビルドが落ちるようにする。
