# 疑い駆動レビュー

## 役割

このスキルは、結論を急いで承認せず、成立条件・反証・代替案を検討するための**専門的な判断枠組み**である。

開発の順序、レビューの必須性、サブエージェントの起動、外部ツールの利用、コミットやマージの可否は規定しない。それらは利用者または上位の開発フローが決める。

## 使う場面

- 不可逆性が高い判断（公開 API、データ移行、権限、課金、本番設定）
- 型やテストだけでは保証できない性質（冪等性、競合安全性、順序、不変条件）
- モジュール境界・依存関係・抽象化の選択
- 「安全」「スケールする」「仕様に合う」といった根拠を確認したい主張

機械的なリネーム、フォーマット、明白な一行変更には通常不要である。

## 判断の進め方

対象について、必要な範囲で次を整理する。

1. **主張。** 何を正しいと見なすか、それがなぜ重要かを書く。
2. **契約と前提。** 入出力、不変条件、依存先、失敗時の期待動作を書き出す。
3. **安全の要になる事実。** 危なく見える変更の多くは、たった 1 つの事実のおかげで安全になっている（「この呼び出しは既に死んだキャッシュの項目だけを捨てる」など）。その事実を見つけ、成り立つなら危険の候補の多くがまとめて消えるかを確かめる。長い「かもしれない」の一覧を作る前に、ここへ時間を使う。
4. **反証。** 主張が崩れる入力、並行実行、障害、運用条件、仕様解釈を挙げる。反証は具体的な実行の経路で示す。上流で検証済み、または型が防いでいる経路は反証にならない。grep が届かない所（呼び出すライブラリのソースと固定したバージョン、実行の時機、API が返す JSON・DB の列・ワイヤ形式・feature flag などシンボル検索に出ない経路）も見る。
5. **根拠。** コード、仕様、テスト、計測、一次資料のどれが主張を支えるかを分ける。主張ごとに、下の「確かさの段階」のどこまで下ろせたかを書く。
6. **代替案と結論。** リスクを下げる案、残余リスク、採用する判断を示す。

同じ前提に立つ修正や設計案が 2 つ以上、同じ関門で失敗しているなら、次の案を検討する前にその前提を書き出して直接確かめる（`35-architect-principle` の `references/pstack-principles/attack-the-premise.md`）。

### 確かさの段階

筋の通った反証の文章は、真偽にかかわらず説得力があるように読めるので、文章そのものを信じない。主張ごとに、安く済む範囲でこの段階を下へ進め、どこで止まったかを書く。

1. そう言っただけ。それだけでは価値がない。
2. 行を指した。実在する `file:line`、またはライブラリ自身のソース。
3. 悪い場合が起きないことを示した。失敗の流れを一歩ずつたどり、届かないことを示した。
4. 動かした。実際のコードを呼び、誤っていれば大きく落ちるスクリプトかテスト。
5. 動いているアプリで再現した。

段階 4 は、たいていアプリが使うのと同じライブラリを import し、心配している関数そのものを呼ぶ小さなスクリプト 1 本で足りる。安全の要になる事実は、段階 4 以上まで下ろすことを目指す。下ろせなかったら「未証明」と書く。

## 出力

結論は次の形で返す。

```markdown
## 疑い駆動レビュー

### 主張
- …

### 前提・契約
- …

### 安全の要になる事実
- <事実>。確かさは段階 <1〜5> で、証拠は <file:line、スクリプトと出力、再現のどれか>。下ろせなければ「未証明」と書く

### 反証または未確認点
- …

### 根拠
- …

### 推奨
- …

### 残余リスク
- …
```

反証が見つからない場合も、「確認した範囲」と「未確認の範囲」を分けて記載する。別の視点や外部レビューが有益な場合は、選択肢として提案してよいが、実施を必須化しない。

## 他スキルとの関係

- `35-architect-principle` は構造上のトレードオフを判断する基準を供給する。
- `35-architect-db-design` と `35-architect-security` は、それぞれの専門領域で確認すべき前提を供給する。
- `35-architect-code-review` は依頼された変更の品質を評価する。疑い駆動レビューは、変更前後を問わず判断の根拠を吟味するために使える。
- `35-architect-interrogate` は、書き上がった差分を複数モデルで敵対的にレビューする。疑い駆動レビューは判断の前提を、interrogate はコードの実行を叩く。
- 「安全の要になる事実」と「確かさの段階」は、[cursor/plugins の pstack `blast-radius`](https://github.com/cursor/plugins/blob/main/pstack/skills/blast-radius/SKILL.md) を取り込んだもの。
